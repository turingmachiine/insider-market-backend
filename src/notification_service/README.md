# Notification Service

`notification_service` отвечает за live-обновления и пользовательские уведомления.

## Зона ответственности

- WebSocket/SSE-каналы для frontend.
- Live-обновления коэффициентов рынков.
- Уведомления о новых событиях, резолюциях и изменениях рейтинга.
- Доставка системных уведомлений пользователю.
- Подписка на внутренние события через Redis Pub/Sub или другой брокер.

## Транспорт и подписки

- WebSocket: основной канал для frontend, которому нужны live-обновления в
  рамках открытой страницы.
- SSE: read-only канал для простых виджетов и административных экранов, где
  не нужен двусторонний обмен.
- Redis Pub/Sub: внутренний брокер первого этапа. При росте требований к
  гарантированной доставке можно заменить adapter на NATS/Kafka без изменения
  presentation-контрактов.

Подписка задается набором topics и опциональным `user_id`.

Текущие topics:

- `market` — изменения коэффициентов, статуса рынка и расчетов.
- `event` — новые события, модерация и резолюции.
- `rating` — изменения рейтинга пользователя.
- `profile` — изменения пользовательского профиля.
- `system` — системные уведомления.

Публичные topic-события доставляются всем подписчикам topic. Если событие
содержит `user_id`, оно дополнительно публикуется в персональный канал
пользователя.

## API

- `POST /api/v1/notifications/events` — принять внутреннее событие и
  опубликовать его в broker.
- `GET /api/v1/notifications/stream` — SSE-подписка.
- `WS /api/v1/notifications/ws` — WebSocket-подписка.

Query-параметры для live-подписок:

- `topics` — один или несколько topics; по умолчанию `market`, `event`,
  `rating`, `system`.
- `user_id` — опциональный UUID пользователя для персональных уведомлений.

## Возможные технологии

- FastAPI WebSocket/SSE.
- Redis Pub/Sub на первом этапе.
- NATS или Kafka при росте нагрузки и требований к гарантированной доставке.

## Границы сервиса

- Сервис не владеет рынками, событиями, рейтингами или профилями.
- Он доставляет изменения, полученные от `market_service`, `event_service`,
  `rating_service` и `profile_service`.
