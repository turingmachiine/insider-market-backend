# Admin Service

`admin_service` отвечает за административную панель, кросс-сервисные
операционные сценарии и backend-for-frontend для администраторов Insider Market.

## Зона ответственности

- Backend-for-frontend для административной панели.
- Агрегация данных для модерации слухов, событий, профилей участников,
  рынков и ошибок обработки.
- Операционные сценарии, которые требуют данных или команд из нескольких
  сервисов.
- Управление событиями через команды `event_service`: approve, reject, resolve,
  cancel.
- Управление профилями участников через команды `profile_service`.
- Управление учетными записями, ролями и блокировками через команды
  `auth_service`.
- Операционные представления для мониторинга проблемных событий, спорных
  профилей, подозрительной активности и ошибок обработки.
- Аудит действий администраторов, saved filters, operational notes и assignment
  задач модераторам.
- Координация запросов к `rumor_service`, `event_service`, `profile_service`,
  `nsi_service`, `market_service` и `auth_service`.

## Границы сервиса

- Сервис не должен владеть доменными моделями слухов, событий, рынков или
  пользователей.
- Сервис не должен хранить копии доменных сущностей как источник истины.
- Сложные изменения должны выполняться через API сервисов-владельцев.
- `event_service` владеет жизненным циклом событий и проверяет допустимость
  переходов статусов.
- `profile_service` владеет публичными и социальными данными профиля.
- `auth_service` владеет учетными записями, ролями, permissions и блокировками
  входа.
- Проверка ролей и permissions должна опираться на `auth_service`.

## API

Базовый путь через gateway: `/admin/api/v1`.

- `GET /dashboard` - сводка по состоянию сервисов, очередям и объемам данных.
- `GET /health` - health summary по подчиненным сервисам.
- `GET /events/moderation-queue` - очередь событий на модерацию.
- `POST /events/{event_id}/approve` - одобрить событие.
- `POST /events/{event_id}/reject` - отклонить событие.
- `POST /events/{event_id}/resolve` - зафиксировать исход события.
- `POST /events/{event_id}/cancel` - отменить событие.
- `GET /users` - список пользователей.
- `GET /users/{user_id}` - карточка пользователя.
- `GET /users/{user_id}/permissions` - permissions пользователя.
- `PATCH /users/{user_id}/status` - включить или отключить пользователя.
- `POST /users/{user_id}/roles` - назначить роль и permissions.
- `GET /profiles/{user_id}/summary` - агрегированный профильный срез.
- `GET /audit/actions` - локальный аудит админских действий.
- `GET /saved-filters` - сохраненные фильтры.
- `POST /saved-filters` - сохранить фильтр.

## Текущий статус

Сервис реализован как отдельный backend-сервис с собственной БД для аудита
и saved filters, DI-контейнером, SQLAlchemy imperative mapping, FastAPI API и
HTTP-клиентом к владельцам доменных данных.
