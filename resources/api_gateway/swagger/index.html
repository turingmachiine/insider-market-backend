Как работает продукт

Backend собирает футбольные инсайды, нормализует их в события и готовит основу для рынка прогнозов с рейтингами участников.

01

Сбор публикаций

ETL-пайплайн забирает посты из Telegram-каналов инсайдеров и спортивных медиа. В проектной модели это сырье для дальнейшей проверки, дедупликации и анализа.

02

Извлечение событий

Rule-based логика выделяет из текста потенциальные события: трансферы, назначения, увольнения, конфликты и другие инфоповоды российского футбола.

03

Модерация и рынок

Администратор проверяет кандидаты, уточняет формулировки и публикует рынки. AMM-логика должна менять коэффициенты после ставок пользователей.

04

Резолюция и рейтинг

После наступления исхода система обновляет результаты, accuracy, ELO и композитный score, чтобы сравнивать участников и источники по исторической точности.

Для кого строится система

Проект закрывает разрыв между хаотичным потоком инсайдов и проверяемой историей прогнозов.

Футбольные фанаты соревнуются в точности прогнозов и следят за рынком слухов
Журналисты получают базу подтвержденных слухов и рейтинг источников
Аналитики и клубы видят тренды, надежность источников и движение трансферных ожиданий

Карта backend-сервисов

Сейчас через gateway доступны реализованные сервисы. Остальные зоны ответственности описаны в README и запланированы для развития prediction market.

api_gateway единая публичная точка входа, CORS, rate limit, проксирование
auth_service пользователи, роли, permissions, JWT
nsi_service футбольные справочники и аналитическая база
rumor_service источники, публикации, слухи, confidence score
event_service жизненный цикл событий, дедлайны и резолюция исходов
etl_service сбор Telegram, СМИ и внешних спортивных API
market_service prediction market, AMM, ставки и ликвидность
rating_service accuracy, ELO, лидерборды и периодические рейтинги
profile_service публичные профили, достижения и социальные связи
notification_service WebSocket, live updates и уведомления
admin_service операционные сценарии модерации и управления событиями
Публичные префиксы: /nsi, /auth, /rumor и /event. Gateway отвечает за CORS, security headers, валидацию путей, лимиты размера запроса, Redis-backed rate limiting, JSON access logs и обработку upstream timeout.
