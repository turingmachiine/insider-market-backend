# Market Service

`market_service` отвечает за Prediction Market, виртуальные коины, ставки,
позиции пользователей и AMM для бинарных рынков `YES/NO`.

## Зона ответственности

- Создание рынка для активного события из `event_service`.
- Учет стартовой вероятности события через начальные виртуальные резервы AMM.
- Прием ставок виртуальными коинами.
- Динамический пересчет вероятностей и decimal-коэффициентов после каждой
  ставки.
- Хранение сделок, пользовательских позиций и кошельков.
- Закрытие и резолв рынков по outcome, пришедшему из `event_service`.
- Начисление выигрыша по позициям или возврат invested amount при `VOID`.

## Механика AMM

Рынок бинарный: пользователь покупает shares исхода `YES` или `NO`.
Shares победившего исхода выплачиваются по 1 виртуальному коину за share.

Начальная вероятность не заменяется фиксированным коэффициентом, а переводится
в виртуальные резервы:

```text
yes_pool = liquidity_parameter * (1 - initial_probability)
no_pool = liquidity_parameter * initial_probability
yes_probability = no_pool / (yes_pool + no_pool)
no_probability = yes_pool / (yes_pool + no_pool)
odds = 1 / probability
```

Покупка `YES` двигает вероятность `YES` вверх с учетом `liquidity_parameter`.
Пользователь получает shares по средней цене между вероятностью до и после
сделки. Поэтому крупная ставка получает худшую среднюю цену, вероятность `YES`
растет, а коэффициент на `YES` падает. Для `NO` применяется симметричная логика.

Так низковероятные события получают высокий стартовый коэффициент, но крупная
ставка быстро двигает рынок, как в prediction market с ограниченной
ликвидностью.

## Реализованные API

- `POST /api/v1/wallets` — создать кошелек пользователя с виртуальными коинами.
- `GET /api/v1/wallets/{user_id}` — получить баланс.
- `POST /api/v1/markets` — создать рынок для события.
- `GET /api/v1/markets` — список рынков с фильтрами по статусу и event id.
- `GET /api/v1/markets/{market_id}` — состояние рынка, вероятности и
  коэффициенты.
- `POST /api/v1/markets/{market_id}/bets` — купить shares исхода.
- `GET /api/v1/markets/{market_id}/bets` — история сделок.
- `GET /api/v1/markets/{market_id}/positions` — позиции по рынку.
- `POST /api/v1/markets/{market_id}/close` — закрыть прием ставок.
- `POST /api/v1/markets/{market_id}/resolve` — резолв и расчет выплат.

## Границы сервиса

- `market_service` не решает, правда событие или нет; итоговый outcome приходит
  из `event_service`.
- Рейтинги пользователей рассчитывает `rating_service`.
- Профиль пользователя хранится в `profile_service`.
- Live-рассылку изменений должен выполнять `notification_service`; текущий
  сервис хранит состояние, из которого эти события можно публиковать.

## Дальнейшие фичи

- Порт публикации market updates в Redis Streams/PubSub для `notification_service`.
- Идемпотентные ставки с client request id.
- Автоматическое закрытие рынка по `close_at`.
- Административные лимиты: max stake, max exposure на пользователя и freeze
  подозрительных рынков.
- Ledger-таблица для полного аудита движения виртуальных коинов.
- Интеграция с `event_service`: авто-создание рынка при approval события и
  авто-резолв при outcome.
