# Rating Service

`rating_service` отвечает за игровые рейтинги и оценку качества прогнозов.

## Зона ответственности

- Расчет пользовательского score.
- Расчет Accuracy и ELO.
- Поддержка периодов: all-time, сезон, месяц, неделя.
- Расчет high-risk bonus.
- Формирование лидербордов.
- Обработка результатов после resolution событий.

## Границы с другими сервисами

- Публичные профили, подписки и витрина достижений находятся в `profile_service`.
- Сырые ставки и позиции принадлежат `market_service`.
- Итоговый outcome события приходит из `event_service`.

## Реализованная модель

Сервис реализован как отдельный bounded context с собственной БД, API и
фоновой обработкой Taskiq. Он не расширяет `etl_service`: ETL отвечает за
импорт и нормализацию внешних данных, а рейтинг обрабатывает внутренние
игровые события, статусы, достижения и награды.

Основной поток:

1. Сервис принимает идемпотентные события `/api/v1/ratings/events`.
2. Событие обновляет XP, rating, level, streak, accuracy, ROI и статус
   пользователя.
3. Правила достижений проверяются автоматически после каждого события.
4. За новое достижение создается pending-награда.
5. Фоновая задача доставляет награду в баланс `profile_service` через
   идемпотентную credit-транзакцию.

## Игровые механики

- Базовый рейтинг стартует с 1000 и не падает ниже 100.
- Успешные прогнозы дают XP, rating и streak-бонус.
- ROI по прогнозу добавляет дополнительный rating-бонус.
- Неуспешный прогноз сбрасывает текущую серию и снижает rating.
- Аналитика, создание рынков, комментарии и daily activity дают малые
  прогресс-бонусы.
- Статусы: `rookie`, `scout`, `analyst`, `expert`, `legend`.
- Достижения имеют редкость и награду в COIN.

## Фоновые задачи

- `process_rating_events_task` догоняет необработанные события.
- `dispatch_rating_rewards_task` повторно отправляет pending/failed награды.

Worker и scheduler запускаются отдельно от HTTP-сервиса, но используют тот же
контейнер зависимостей и доменную логику.

Расписания Taskiq jobs задаются в
`resources/rating_service/taskiq/jobs.yml`. Путь внутри контейнера задается
через `TASKIQ_JOBS_CONFIG_PATH`.
